### 작업 내용
- `ShipmentOrderController.getWavePatternSort`, `getWavePatternSortById` 메서드를 `index` 메서드처럼 페이지네이션 처리
- 기존 `List<ShipmentOrder>` 반환에서 `Page<ShipmentOrder>` 반환으로 변경

- 서비스 레이어에 COUNT 쿼리 추가 및 `selectListBySql` 오프셋/페이지 크기 적용

### 변경/생성 파일
- `src/main/java/operato/wms/oms/service/OmsShipmentOrderService.java`
  — `getWavePatternSortedOrders`, `getWavePatternSortedOrdersByWaveId` 시그니처 변경: `page`/`limit` 파라미터 추가, 반환형 `List` → `Page<ShipmentOrder>`, COUNT 쿼리 추가
- `src/main/java/operato/wms/oms/rest/ShipmentOrderController.java`
  — `getWavePatternSort`, `getWavePatternSortById` 반환형 `List` → `Page<?>`, `@RequestParam page(기본값:1)` / `limit(기본값:50)` 추가

### 주요 결정 또는 발견 사항
- `Page` 클래스(`xyz.elidom.dbist.dml.Page`)는 `@JsonProperty("total")=totalSize`, `@JsonProperty("items")=list`이므로 응답이 `{ "total": N, "items": [...] }` 구조
- COUNT 쿼리는 CTE를 재사용하지 않고 간단한 `COUNT(DISTINCT so.id)`로 별도 실행 (성능·단순성 균형)
- `firstIndex = (page - 1) * limit` (0-based offset), `safeLimit = 0`이면 전체 반환 (`selectListBySql` 규격)
- `lastIndex = ceil(total / limit)` 로 마지막 페이지 번호 계산
