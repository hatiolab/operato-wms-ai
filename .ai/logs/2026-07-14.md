## 22:40 — PickingTaskItem.stock_allocation_id null 케이스 분석

### 작업 내용
- 토털 피킹 생성 로직(`createTotalPickingOrdersByWave`)에서 `stock_allocation_id`가 세팅되지 않는 이유 분석
- 규칙 위반 여부("할당 없이 피킹 지시 생성 불가") 검토

### 주요 결정 또는 발견 사항
- 버그 아님 — 설계상 의도된 null
- 토털 피킹은 `PickingTaskItem 1건 = 여러 주문의 StockAllocation 합산`이므로 단일 `stock_allocation_id` 지정 불가
- 개별 피킹: 1:1 매핑 가능, 토털 피킹: N:1 구조라 `inventoryId + waveNo`로 할당 특정
- `deallocateShortQtyInTotalPicking()`이 `stock_allocation_id` 대신 `inventoryId + waveNo` 조건을 사용하는 이유도 동일한 구조적 이유

## 23:00 — 토털 피킹 결품 재할당 시 StockAllocation 주문 연결 보장

### 작업 내용
- 토털 피킹 SHORT 처리 후 재할당 시 `shipmentOrderId = null`인 `StockAllocation`이 생성되어
  `closeShipmentOrder()`에서 RELEASED 처리가 누락되는 문제 발견 및 수정
- `deallocateShortQtyInTotalPicking()` 반환값을 `void → List<Map<String,Object>>`로 변경하여
  주문별 해제 수량 내역(order_id, order_item_id, shipment_no, biz_type, released_qty) 반환
- `reallocateShortQtyInTotalPicking()`에서 반환된 breakdown을 활용해
  대체 재고 할당 시 주문별로 `StockAllocation`을 개별 생성 (shipment_order_id 연결 유지)
- `PickingTaskItem`은 여전히 재고(로케이션) 단위 집계 1건으로 추가하여 피킹 UX는 변화 없음

### 변경/생성 파일
- `src/main/java/operato/wms/fulfillment/service/FulfillmentPickingService.java`
  - `deallocateShortQtyInTotalPicking()`: 반환 타입 void → List<Map<String,Object>>, stock_allocations + shipment_orders JOIN 쿼리로 주문 정보 함께 조회, 해제 내역 반환
  - `reallocateShortQtyInTotalPicking()`: releasedBreakdown 파라미터 추가, 가용재고 × 주문 2중 루프로 주문별 할당 분산 생성
  - `shortItem()`: 두 메서드 사이에 breakdown 전달하도록 호출부 수정

### 주요 결정 또는 발견 사항
- 토털 피킹의 `PickingTaskItem.stock_allocation_id = null`은 설계상 의도 (1:N 구조)이지만,
  재할당 생성 시에도 `stock_allocations`에는 반드시 `shipment_order_id` 연결 필요
- deallocate 단계에서 어느 주문이 얼마나 해제됐는지 breakdown을 추적하여 reallocate에 전달하는 방식으로 해결
- B2C 주문 재할당은 biz_type 기반으로 SOFT 상태 유지
