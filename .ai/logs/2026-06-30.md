## 11:00 — MULTI_BARCODE_SHEET PDF 다중 페이지 미출력 원인 분석 및 수정

### 작업 내용
- '인쇄' 버튼 → `InboundTransactionController.downloadBarcodeSheetForReceiving` → `MULTI_BARCODE_SHEET` 템플릿 실행 경로 전체 추적
- 기존 `<group isStartNewPage="true">` 방식이 barcode 필드 값 변경에만 의존하여 barcode가 null이거나 동일한 경우 1페이지만 생성되는 문제 확인
- DB 템플릿을 `<detail><band height="780" splitType="Prevent">` 방식으로 교체
- barbecue null 처리 추가: `$F{barcode} != null ? $F{barcode} : "NO_BARCODE"`

### 변경/생성 파일
- DB `diy_templates` (domain_id=16, name='MULTI_BARCODE_SHEET') — group 방식 → detail 밴드 방식으로 교체

### 주요 결정 또는 발견 사항
- **근본 원인**: `isStartNewPage="true"` 그룹은 그룹 expression 값(barcode)이 변경될 때만 페이지 브레이크 삽입 → barcode null 시 1개 그룹 → 1페이지
- **수정 방식**: detail 밴드 height=780px + splitType="Prevent" → 페이지 컨텐츠 822px에서 2번째 밴드는 남은 42px에 들어갈 수 없으므로 다음 페이지로 이동 → N레코드 = N페이지
- `PdfPrintingService`의 List → `{"rows":[...]}` 래핑 + `JsonDataSource(stream, "rows")` 코드는 이미 정상이므로 유지
- `FormatUtil.toUnderScoreJsonString`은 Gson 기반으로 Map 키는 변환하지 않음 (snake_case 유지됨)
